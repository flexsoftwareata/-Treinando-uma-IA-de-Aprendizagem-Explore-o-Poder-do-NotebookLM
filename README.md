# Tema: Frontend e UI/UX em ERPs Tradicionais
 Objetivo: Maximizar o padrão visual e a usabilidade dos meus ERPs pessoais por meio de engenharia de prompts detalhada, orientando a geração de código pelo Codex com foco em alta performance e design consistente.

Explicando as fontes:
### 1\. Design Systems, Design Tokens e Governança Visual

Essas fontes fornecem a base metodológica para criar sistemas de design coesos, escaláveis e preparados para automação e múltiplos produtos.

* **7 Enterprise Design System Best Practices and Trends for 2026**: Explica como gerenciar um Design System como um produto interno, estruturar arquiteturas de tokens semânticos no padrão DTCG e integrar repositórios com agentes de IA via Model Context Protocol (MCP).
* **From Vision to Reality: The Roadmap to Building an Enterprise Design System - Apiko**: Oferece um roteiro prático para a construção de bibliotecas de componentes, guias de estilo, padrões de layout e modelos de governança (centralizada, federada ou solitária).
* **Criando uma linguagem de design coesa e eficiente com design tokens - UX Collective**: Detalha como implementar e nomear tokens atômicos de design para garantir consistência visual e eficiência na manutenção entre equipes.
* **Iteração UX/UI: refinamento de interface com design system e tokens visuais**: Ilustra o processo prático de iteração e refinamento de interfaces alinhando tokens visuais diretamente no fluxo de design.

### 2\. Engenharia de Dashboards, Tabelas de Dados e Visualização

Aplicações corporativas modernas lidam com grandes volumes de dados. Este grupo aborda como estruturar visualizações claras e otimizar a manipulação de dados pesados.

* **Building Modern Tailwind CSS Dashboards: A Developer's Complete Guide - DhiWise**: Guia prático de desenvolvimento com Tailwind CSS para prototipar e estruturar componentes de navegação, tabelas e gráficos responsivos.
* **A Front-End Engineer's Guide to Designing Interactive Dashboards - Dataversity**: Aborda o manuseio de grandes conjuntos de dados no frontend utilizando virtualização de listas, paginação, *throttling* e técnicas de renderização em tempo real.
* **Data Table Design UX Patterns &amp; Best Practices - Pencil &amp; Paper**: Detalha padrões de UX/UI para tabelas corporativas, cobrindo alinhamento visual, congelamento de colunas, ordenação, densidade de exibição e edições *inline*.
* **Enterprise UX: essential resources to design complex data tables - Stéphanie Walter**: Reúne recursos e padrões para tabelas complexas (*data grids*), focando em como organizar informações densas e adaptá-las para telas menores ou cenários móveis.
* **Design Patterns to Support the Usability and User Experience Evaluation of Dashboards for Decision Support Systems - Journals**: Apresenta o *DP-DASHBOARD*, um conjunto acadêmico de padrões de design para dashboards de apoio à tomada de decisão.
* **Designing UX/UI for Data-Heavy Apps: A Guide to Clarity and Efficiency - UIUX Studio**: Explora hierarquia de informação, revelação progressiva (*progressive disclosure*) e estética minimalista para evitar sobrecarga cognitiva em sistemas analíticos.
* **Designing for Clarity: UX/UI Best Practices for Data-Heavy SaaS - Creative27**: Foca na arquitetura de informação, divisores de seção, paletas de cores desaturadas e suporte à navegação em SaaS de alta densidade de dados.
* **VCU DASHBOARD DEVELOPMENT GUIDELINES**: Estabelece critérios e *checklists* de elegibilidade institucional para diferenciar dashboards estratégicos e táticos de relatórios estáticos, focando em segurança e tendências temporais.

### 3\. Arquitetura Frontend, Performance e Otimização

Projetar para escala requer técnicas avançadas de renderização, divisão de código e desacoplamento de código.

## Diretiz do agente: 
Você é um desenvolvedor Frontend Senior especialista em UI/UX para sistemas de alta densidade de dados (ERPs).

## Pergunta realizada:

Crie o prompt perfeito para que eu crie o Frontend do meu aplicativo de gerenciamento de um personal trainer que dejesa controlar os treinos dos meus alunos, eles querem ver os vídeos treinos acompanahr resultados e comentários

### Resposta:

Para criar um aplicativo de alta qualidade usando ferramentas de codificação por IA (como **v0, Lovable, Cursor, Bolt, Fardino ou Claude Code**), um prompt vago como *"crie um app de personal trainer"* gera resultados genéricos.

Para obter um código pronto para produção, usamos a **fórmula de 5 elementos da engenharia de prompts para UI assistida por IA**[1]: **Contexto/Papel + Objetivo da Aplicação + Arquitetura de Layout/UX + Especificações das Funcionalidades + Stack Técnica &amp; Regras de Design**[2].

Abaixo está o **Prompt Mestre** estruturado e pronto para copiar e colar na sua ferramenta de IA favorita.

---

### 📋 Prompt Mestre para Copiar e Colar

```
ROLE &amp; CONTEXTO:
Você é um Engenheiro Frontend Senior especialista em UI/UX para aplicações SaaS modernas, fitness e dashboards operacionais. 
Crie a interface frontend completa, responsiva e mobile-first para um Web App (PWA) de gerenciamento de treinos focado na relação entre Personal Trainer e seus Alunos.

OBJETIVO DO PRODUTO:
Permitir que o Personal Trainer monte e acompanhe treinos e que os Alunos executem seus treinos diários, assistam a vídeos demonstrativos das séries, registrem cargas/repetições e troquem comentários/feedbacks em tempo real sobre a execução.

ARQUITETURA DE TELAS &amp; ESTRUTURA DE NAVEGAÇÃO:
A aplicação deve possuir uma navegação clara adaptada para dois perfis de usuário:

1. VISÃO DO ALUNO (Mobile-First / PWA):
   - Home / Treino do Dia: Card de destaque com o treino agendado (ex: "Treino A - Peito e Tríceps"), progresso semanal (barra de progresso e ofensiva de dias) e atalho rápido "Iniciar Treino".
   - Player e Execução de Exercícios:
     * Player de Vídeo em destaque no topo (vídeo embed/HTML5 com suporte a looping e controles de velocidade).
     * Card explicativo com: Nome do Exercício, Séries x Repetições, Carga Sugerida e Tempo de Descanso com cronômetro/timer regressivo interativo.
     * Tabela/Checklist de Séries: onde o aluno marca a série como concluída e pode ajustar a carga real utilizada.
   - Acompanhamento de Resultados: Gráficos de evolução de carga por exercício, gráfico de frequência mensal e histórico de medidas corporais.
   - Thread de Comentários / Feedbacks: Aba ou Drawer em cada exercício/treino para enviar dúvidas ou observações ao Personal ("Ex: Senti dor no ombro esquerdo na 3ª série").

2. VISÃO DO PERSONAL TRAINER (Dashboard Desktop / Tablet):
   - Gestão de Alunos (Data Grid): Tabela com foto, nome, plano, status de frequência semanal e último treino realizado.
   - Construtor de Treinos: Interface drag-and-drop/list-builder para selecionar exercícios de uma biblioteca, vincular links de vídeo, definir séries/reps e atribuir ao aluno.
   - Central de Feedbacks &amp; Notificações: Feed com os comentários recentes dos alunos sobre os treinos para resposta rápida.

ESTILO VISUAL &amp; DESIGN SYSTEM:
- Tema: Dark-mode-first por padrão, com estética moderna e atlética (inspiração em apps como Strava, Nike Training e Linear).
- Cores: Fundo escuro (#0a0a0a e #121212), texto primário de alto contraste (#ffffff), cor de acento energético (Verde Neon #22c55e ou Laranja elétrico #f97316) para botões de ação e status ativos.
- Tipografia: Inter ou Sans-Serif moderna, hierarquia visual bem definida e numerais destacados para tempos e cargas.
- Componentes: Utilizar padrões do Tailwind CSS + Shadcn/UI (Cards arredondados, Badges de status, Modal/Drawer para comentários, Abas e Sliders).

STACK TÉCNICA:
- Framework: React com TypeScript e Tailwind CSS.
- Ícones: Lucide React (play, check-circle, clock, message-square, dumbbell, trending-up).
- Gráficos: Recharts ou Chart.js (gráfico de linha para evolução de carga e gráfico de barras para frequência).
- Animações: Framer Motion para transições suaves entre exercícios e contadores.

REGRAS DE CÓDIGO E ENTREGÁVEIS:
- Entregue o componente principal modularizado com estado local simulado (mock data realista).
- O player de vídeo deve conter fallback elegante para vídeos do YouTube/Vimeo ou MP4.
- Inclua estados visuais para: "Em andamento", "Treino Concluído" e "Série Concluída".
- Garanta acessibilidade (WCAG), alvos de toque mínimos de 44x44px no mobile e navegação por teclado [6, 7].

```

### 🧠 Por que este prompt funciona?

1. **Evita o visual "AI Genérico"**: Ao especificar o contraste, paleta escura e referências visuais (Strava/Linear), o agente de IA utiliza tokens visuais semânticos e hierarquia clara em vez de inventar layouts ultrapassados[6][7].
2. **Foco na Carga Cognitiva**: Para a tela de execução do aluno, o prompt força uma estrutura orientada a etapas (*progressive disclosure*), separando o vídeo de instrução, o cronômetro e a área de anotações para não poluir a tela do celular[8][9].
3. **Contrato de Funcionalidades Claro**: Define exatamente o que deve estar no player, como o cronômetro interativo e os comentários por exercício funcionam, reduzindo alucinações de código[10][11].
